# 网站产品与实现决策问卷

本问卷用于在实际代码开发前补齐产品、体验、视觉、内容、技术与运营选择。它面向非产品、非前端专业人员编写；选项中的建议只是专业推荐，不会在人工选择前自动成为项目结论。

最终实现依据仍是 `docs/blueprint/06_决策清单.csv` 及其关联蓝图。本问卷只负责收集选择；回答确认后，应一次性回填决策清单、核心蓝图、功能目录、旅程、模块和内容方案，不能让问卷成为第二套实现规范。

## 如何回答

- `P0`：开始 M0 编码前必须回答，否则会影响页面骨架、数据或技术结构。
- `P1`：安装购票、i18n、小游戏等插件或扩展公开内容前回答。
- `P2`：可在专题设计前回答，不阻塞 M0。
- 每题的 A 是当前推荐方案，除非题目明确说明“可多选”。
- 可直接回复 `A01-A，A02-C，B03-A`，也可在选项后补充说明。
- 如果认可某一优先级的全部推荐项，可回复“P0 全部 A”；需要例外时再列出，例如“P0 全部 A，但 H01-B、F07-C”。
- 如果确实无法决定，请明确回复“暂时还未想好”；该项会保留为待决定，不会由 agent 猜测。
- 可以分批回答，例如先回答全部 P0，再回答 P1、P2。
- 如果现有选项都不合适，可写 `自定义：……`。

## 常用词语

- **M0**：最小验证网站，用于证明页面骨架、技术架构、视觉方向和插件接入方式可行。
- **插件**：可以后装、失败时不拖垮基础网站的功能块，例如购票、i18n 和小游戏。
- **静态生成**：在发布前把资料构建成 HTML；访问时不需要网站服务器临时计算页面。
- **SSR**：每次访问时由服务器生成页面，适合账户和实时数据，但部署与维护更复杂。
- **设计 token**：颜色、字号、间距等可重复使用的命名变量。
- **响应式**：同一网站根据手机、平板和电脑宽度重新排版。
- **SEO**：让搜索引擎正确理解标题、页面和链接。
- **预览环境**：正式上线前供人工访问的临时网站，可以由合并请求自动生成，也可以部署到受限 Linux 环境。
- **示例内容**：在 M0 编码前由 agent 依据网站需求和 `background` 事实边界生成，经人工初审后才进入独立示例数据集；它只验证版式、功能、内容表达和沉浸效果，不进入背景事实库，也不自动成为人工启用内容。

### A02 `[P0·已决定]` M0 应该以什么状态交付？

**人工结论：自定义 A。** M0 交付具备完整路由和响应式页面的真实网站。完整实现提交前必须完成本地优化构建并启动产物检查；阶段合并或验收前，将同一提交部署到另一台 Ubuntu 或受访问控制的 ECS，再从手机和电脑访问验证。无域名不等于受限访问，未来正式托管平台另行决定。

- A（推荐）：可通过公开或受限网址访问的真实网站原型，具备完整路由和响应式页面。
- B：只在本地运行，用于开发者验证。
- C：只制作可点击设计稿，不生成真实网页。
- D：首页可访问，其他页面仍使用静态图片演示。

### A03 `[P0·已决定]` M0 页面范围如何组织？

- B：缩减为首页、日历、详情、剧团四类页面。
- C：只做首页和一个演出详情页，最快验证视觉。
- D：在现有范围上提前加入预约页。

### A04 `[P0·已决定]` 首页最重要的第一个行动是什么？

普通页面逐字段回退到炎国配置，官方专名优先使用当前现实语言字段。公开页面以融入式小字标注“中文原文”，开发预览另标“待译”；不自动机器翻译。搜索是明确例外：当前 `localeProfileId + siteEditionId` 组合的索引与结果不使用炎国回退，缺少当前组合必要搜索文本的记录不进入索引。

### G03 `[P1]` 首个多语言版本是否要求四个首批配置的所有 M0 页面同时完整？

- A（推荐）：是；炎国、东国、维多利亚和哥伦比亚通过同一验收后一起发布。
- B：先发布炎国，再逐页补其他三个配置。
- C：只保证首页和演出页四个配置完整。
- D：其他三个配置只保留专名，不翻正文。

### G04 `[P1]` 首批四个配置之后，优先完成哪个后续配置？

- A（推荐）：莱塔尼亚，用于同时验证德语排版和 LED 币种占位。
- B：叙拉古，用于验证意大利语内容与弗洛林显示。
- C：根据当时素材和译文完成度排序，不预先固定。
- D：暂时还未想好，不在首批四项之后立即增加配置。

### G05 `[P1·已决定]` 专名在正文中怎样显示？

普通页面只显示当前地域配置中的专名，不因中英日资料较完整就在首次出现时展开对照。跨语言名称只在证据或编辑预览中显示。

### G06 `[P1·已决定]` 地域配置和地区币种由谁最终批准？

由项目负责人逐项批准；agent 只提出候选、占位和影响说明。资料完整度、Wiki 中存在国家实体或语言候选均不能自动启用运行时配置。

### G07 `[P1·已决定]` 示例内容从哪个配置开始？

M0 编码前先生成完整炎国示例草案，经人工初审后进入独立示例数据集；架构通过后为同一内容补东国、维多利亚和哥伦比亚版本，各配置内容同样需要初审。维多利亚与哥伦比亚共享英文基础资源并分别维护英式、美式覆盖，不复制整套英文内容，也不合并搜索索引。

## 回答后的系统性处理

收到回答后，agent 应执行以下工作，而不是只在本问卷中记录答案：

1. 检查答案之间是否矛盾，并只询问确实无法同时成立的冲突项。
2. 将结论写入 `docs/blueprint/06_决策清单.csv`，为新增决定分配连续编号。
3. 同步修改核心蓝图、设计系统、功能目录、旅程、模块契约、i18n 和内容生产说明。
4. 删除或改写被新结论取代的旧方案、旧名称、旧路由和旧阶段描述。
5. 在 M0 编码前单独生成示例内容草案，人工初审后才建立 `docs/content/90_examples/` 数据集；示例内容不得写入背景事实层或与人工启用内容混合。
6. 使用同一批经初审示例内容制作两套符合既定边界的小型风格板和关键页面线框，人工选定一个视觉基线后再进入完整页面开发。
7. 重新检查 M0/M1/M2/M3 边界、输入路径、自然定位字段和模块依赖。
8. 在真正开始完整页面代码前，给出最终技术栈、目录结构、M0 验收条件和第一批开发任务。
