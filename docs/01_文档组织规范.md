# 文档组织规范

## 1. 分层规则

新增或修改信息时，按以下顺序判断归属：

1. 描述《明日方舟》世界、人物、事件、物件或官方词形的内容，进入 `background/`。
2. 基于事实提出页面文案、叙事用法、创意方向、工作译或编辑判断的内容，进入 `content/`。
3. 描述页面结构、交互、功能、数据契约、部署方式或技术实现的内容，进入 `blueprint/`。
4. 描述来源分级、审核事项、覆盖缺口或跨领域推进工作的内容，进入 `planning/`。

同一段同时包含事实与建议时必须拆分：事实层保留可核对的陈述，应用层通过相对路径与自然定位字段关联事实，不反向复制事实全文。

## 2. 唯一来源与跨表关联

- 每项事实只设置一个规范维护位置。Markdown 图鉴等人工阅读视图必须注明其原子事实来源；更新事实时先改 CSV，再更新衍生视图。
- 两组信息在职责或可信等级上有明确差异时保持分表，例如世界事件与专题解读、关系事实与内容应用、官方词形与工作译。
- 两组信息没有独立维护价值且可以无歧义合并时，应合并到同一表，避免只为连接表而维护连接表。
- 跨表关联使用 `docs/` 起始的仓库相对路径，加足以定位记录的自然字段；不建立中央路径注册表或记录身份索引。
- 自然定位字段应优先选择已有且可读的组合，如“所属 + English”“泰拉时间 + 事件”或完整关系四元组。若自然字段发生变化，须同步检查其使用处。

## 3. 格式选择

| 信息形态 | 首选格式 | 说明 |
| --- | --- | --- |
| 连续说明、事实边界、人工阅读入口 | Markdown | 标题层级稳定，表格只用于短而规则的对照 |
| 可逐行扩展的名录、事件、关系、术语和审核事项 | CSV | 使用 UTF-8 with BOM；首行为字段名；一行一个原子记录 |
| 第三方图像证据 | 公开来源 URL + 文字说明 | 原图不进入仓库，也不建立文件名或路径索引；可回溯事实由公开来源和文字证据维护 |
| 技术配置、结构契约和模块定义 | YAML、JSON | 只进入 `blueprint/`，不作为面向人工的背景正文 |

CSV 应优先包含自然识别字段、事实或内容字段、来源、审查状态和必要备注。官方词形、工作译和语言学推拟必须使用不同字段或不同数据集，不能混写成同一可信等级。

## 4. 命名与排序

- 同级主题目录及有明确阅读顺序的文件使用两位前置序号，如 `background/01_world/`、`background/01_world/02_国家实体.csv`。
- 相似或连续内容使用连续编号，并在所属 `README.md` 中解释阅读顺序。
- `README.md` 是目录入口，不加序号。
- 具有自然标识的模块和结构契约文件可保留其机器名，如模块 YAML 和旅程图编号。
- 编号只控制显示顺序。调整目录或文件编号时，必须全库更新指向该路径的说明、配置与链接。

第三方原图不得进入仓库，也不得建立私有文件名、相对路径或本地挂载约定。agents、自动化与网站构建不得访问仓库外的人工私有备份；公开交付只使用项目原创或已经取得必要授权的视觉资产。

## 5. 多语种边界

- `background/03_terminology/` 只保存拥有官方信息或明确资料转录依据的简中、英文、日文专名。
- `content/03_localization/` 保存创意内容的多语版本、工作译、泰拉语域方案和人工审核队列。
- `blueprint/05_i18n/` 保存地域展示配置、现实语言标签、路由、货币绑定和回退规则等技术实现。
- 缺少官方中文时，官方中文字段留空；工作译进入内容层并保留依据、来源与状态。

## 6. 维护流程

1. 先确认新增内容的层级和唯一维护位置。
2. 更新原子事实或规范文件，并保留原来源与审查状态。
3. 更新关联该事实的衍生视图、创作应用或蓝图输入路径。
4. 检查仓库相对路径、自然定位字段唯一性、CSV 结构和资产路径存在性。
5. 将未解决的证据问题、跨领域决策或覆盖缺口登记到 `planning/`，不要用待办记录替代事实本身。
