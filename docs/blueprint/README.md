# 猩红剧团网站蓝图池

蓝图池回答“网站怎样设计、开发和部署”。`../background/` 只供人工与 agent 准备内容、核对事实边界；网站核心、旅程和模块只读取经审核的 `../content/` 内容集，不直接构建、转换或索引 background。

## 读取顺序

1. `01_core/01_专业演出网站基线.md`：任务型菜单、日历、详情、票务状态和到访。
2. `01_core/04_最小实现.md` 与 `01_core/05_架构.md`：可独立部署的 M0 核心。
3. `07_功能目录.csv`：功能、主旅程、辅助旅程和开发批次。
4. `03_journeys/README.md` 与 `03_journeys/journey_registry.yaml`：点击、恢复与无障碍路径。
5. `04_modules/*.yaml`：模块依赖、输入、降级和验收。
6. `02_contracts/`：旅程与模块的结构校验规则。
7. `05_i18n/`：地域展示配置、现实语言标签、路由、货币和回退关系。

## 目录职责

| 目录或文件 | 职责 |
| --- | --- |
| `01_core/` | 产品边界、实现范围、架构和设计系统 |
| `02_contracts/` | 旅程与模块的结构契约 |
| `03_journeys/` | 用户旅程注册表和 Mermaid 路径图 |
| `04_modules/` | 可插拔功能模块定义 |
| `05_i18n/` | 技术 i18n 与地域展示配置 |
| `06_决策清单.csv` | 已决定、待细化与待决定事项的统一记录 |
| `07_功能目录.csv` | 功能的唯一目录 |

## 单一来源

- 功能描述只在 `07_功能目录.csv`；旅程只使用功能名。
- 模块清单只在 `04_modules/README.md`；模块细节在各 YAML。
- 购票价格、七个结局、导演、本地状态和组合印章的详细规则只在 `04_modules/01_购票体验契约.md`。
- 客席岗位推演只在 `../content/04_performance/02_剧团岗位推演.csv`。
- 演出相关干员事实只在 `../background/04_performance/01_干员事实.csv`。
- 网站版本与内容集契约只在 `../content/05_site_editions/README.md`；核心壳的内容输入只在 `01_core/05_架构.md` 声明，可插拔模块的 `信息输入` 只在各模块 YAML 声明，旅程注册表不重复维护。
- 内容记录可以用来源路径和自然定位字段回溯 background，但这些字段只用于准备与审阅，不构成运行时依赖。

## 当前阶段门

当前优先完善信息库、蓝图、用户旅程和功能元素方案，不初始化具体网页框架。进入实际代码开发前，应先统一裁定会影响产品边界、数据模型或技术选型的关键事项，并在 `06_决策清单.csv` 的“人工结论”中留下明确记录。

所有旅程和新增功能默认“待审”；需要选择的事项记录在 `06_决策清单.csv`。其中“当前建议（非结论）”只用于比较方案，不代表已经批准；只有状态和“人工结论”共同表明已决定的事项才可作为实现依据。状态为“待决定”且“人工结论”为空时，任何建议均不得视为实现依据；“待细化”事项只能使用已明确的原则，不能自行补出数量、名称或路线。仓库已经生效的第三方素材、隐私和无障碍边界不属于可由该清单建议覆盖的产品选择。
