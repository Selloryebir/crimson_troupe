# 参考代码结构

```text
src/
  app/                         # SSR 路由壳：/、/schedule、/troupe、/repertoire、/visit
  core/
    navigation/                # 任务型菜单、面包屑、持续票篮与闭幕入口
    content/                   # docs 资料路径、CSV/Markdown/YAML 只读适配器
    contracts/                 # ContentRecord、Production、Performance、Venue、TicketState
    journeys/                  # 旅程 ID、路由守卫、恢复动作；不复制旅程文案
    i18n/                      # 交付语言与泰拉语域分离
    narrative/                 # 时间层、剧透、稳定模式状态机
    accessibility/             # 动效、声音、高对比、低带宽、无计时
    slots/                     # 声明式模块挂载点
  modules/                     # 每个可选模块独立目录
  content-generated/           # 构建产物；不手改
  components/
  styles/tokens/
  tests/
    contracts/                 # schema 与输入路径校验
    journeys/                  # 每个 JRN 的 happy/recovery/keyboard 路径
    accessibility/
    narrative-state/
    visual/
public/
  assets/                       # 仅放项目原创或已取得必要授权的素材
  print/
scripts/
  ingest-docs.*
  validate-content.*
  validate-journeys.*
  generate-ticket.*
```

模块内部只暴露入口、路由、状态、内容适配器、降级组件和测试；不得导入其他模块内部文件。构建顺序是：验证输入文件与自然定位字段 → 生成只读内容快照 → 校验路由/插槽/依赖 → 生成交付语言页面 → 跑 M0 核心及每条旅程的恢复路径 → 再安装增强模块。
