## 前端技术基线

- 使用 Astro + TypeScript 以静态模式生成公开页面、路由和搜索快照。当前不建立 SSR、API、数据库、账户或托管平台运行时依赖；新需求须另行立项。
- Astro 负责路由、页面和静态组件。React 只用于搜索筛选、购票、小游戏等需要浏览器状态的交互岛；不建立全站 React SPA，不混用第二套交互框架，静态组件不水合。
- JavaScript 依赖只使用 pnpm；仓库只维护 `pnpm-lock.yaml`，`package.json` 声明 `packageManager`，并在初始化时固定受所选 Astro 版本支持的 Node LTS 版本。本地和自动化使用冻结锁文件安装，不并存 npm 或 yarn 锁文件。
- 样式使用原生 CSS Layers 固定全局级联顺序，设计 token 管理可复用语义，Astro 与 React 组件使用局部样式。不引入 Tailwind、CSS-in-JS 或单一全局巨型样式表。`siteEditionId` 映射语义 token；M0 只实现表网站映射，不预建 M3 空色板。

## 内容校验语义

内容契约对当前启用的内容集、地域配置和网站版本执行以下唯一分类：

- 必需字段缺失、主键重复、路由冲突、必需关系或实际输出链接失效时，构建失败。
- 明确标为“待补”的可选字段显示当前地域配置的占位并进入构建报告；占位不代表获得正式发布许可。
- 对当前记录不适用的字段直接省略，不生成占位或警告。可选关联失效时不生成坏链接，而是省略并报告。
- 搜索仍按 `localeProfileId + siteEditionId` 隔离；缺少当前语言必要搜索文本的记录从该索引排除并报告，不使用炎国回退或其他语言字段填充。

必需、待补可选和不适用是内容契约语义，不在适配器中根据空值猜测。构建报告是当次校验产物，不回写内容文件，也不另建一份长期状态库。

## 代码质量边界

- TypeScript 使用严格模式；`astro check` 负责 Astro 文件和项目级类型诊断。
- ESLint 只负责 TypeScript、React 和 Astro 语义检查；Prettier 及 Astro 插件只负责格式化；Stylelint 只负责 CSS 和 Astro `<style>`。
- ESLint 和 Stylelint 关闭与 Prettier 重复的纯格式规则。不引入 Biome、第二套 linter、第二套 formatter 或独立组件展厅框架。
- 前端初始化时将内容契约、类型、lint、格式、样式、单元测试、浏览器测试和静态优化构建分成职责清楚的命令。H13 已在[发布与维护](07_发布与维护.md#合并请求分类与证据)中固定自动执行边界，不改写工具职责；工作流只在前端工程与首个成功检查存在后建立。

模块内部只暴露入口、路由、状态、内容适配器、降级组件和测试；不得导入其他模块内部文件。构建顺序是：选择一个经审核的 `docs/content` 内容集 → 校验 `contentSetId`、`siteEditionId`、`localeProfileId`、路由清单和自然定位字段 → 由类型化适配器生成只读内容快照 → 按 `localeProfileId + siteEditionId` 生成隔离搜索索引 → 校验地域配置、路由、插槽和依赖 → 跑当前批次旅程的主流程与恢复路径 → 验证 i18n 接入面 → 再启用其他地域配置与增强模块。构建器不得读取或索引 `docs/background`。

M0 编码前另设内容准备门：agent 先生成示例草案，人工初审后才建立 `docs/content/90_examples/01_m0/` 并允许 demo 构建读取。示例集与人工编辑并启用的内容共享契约和适配器，但一次构建只能选择一个内容集；正式发布引用示例目录时必须失败。当前决策修正文档时不创建示例数据。

示例内容初审后、完整页面开发前另设视觉选择门：agent 使用同一内容制作两套符合既定边界的小型风格板和关键页面线框；人工选定一个 M0 表网站基线后，才建立正式 token、组件展厅和完整页面。两套风格板不是运行时主题，也不为 M3 预建样式。

轻量组件展厅复用正式组件、token 和经过初审的示例数据，只在开发环境与预览构建的受限入口中生成；不引入独立组件框架，也不进入正式导航或生产站点地图。

M0 只把 `siteEditionId = new-dionysus` 作为内容、搜索和语义配色边界，不生成 M3 页面、切换器、配色映射或异常状态机。M3 的历史网站模块使用独立路由清单、页面组件和版本配色；只有语义确实相同的底层工具可以复用，不能要求表里网站拥有相同页面、记录数量、功能或视觉模板。

自动化测试不另建重复的类型或 lint 检查。单元测试必须覆盖内容适配器、`localeProfileId + siteEditionId` 搜索隔离和关键数据关系；浏览器测试覆盖当前批次核心旅程，后装插件再补自身主流程与恢复路径。浏览器截图只作视觉辅助，不能替代路由、状态、可见结果和恢复动作断言。
