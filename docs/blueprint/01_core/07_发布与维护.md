# 发布与维护

本文件是内容更新、阶段发布、正式收录、上线后排序和故障回退的唯一流程蓝图。它规定跨 M0～M3 的稳定边界，不提前选择尚未决定的前端工具，也不替代 H13 后续统一设计的分支、标签、Ruleset、合并请求模板和自动工作流。

## 发布输入分类

是否进入网站发布链路由变更语义决定，不能把所有 `docs` 修改一概视为公开内容更新。

| 变更 | 自动处理 | 发布边界 |
| --- | --- | --- |
| `docs/background/`、`docs/blueprint/`、`docs/planning/` 的资料或规范 | 运行仓库文档、结构、引用和契约校验 | 不作为网站内容输入，不因单独修改而发布网站 |
| `docs/content/90_examples/` 中经初审的示例集 | 可以生成显式选择示例集的 demo 构建 | 正式构建必须拒绝引用，不得原地转正 |
| 构建入口选定的正式内容集 | 运行内容契约、网站构建、受影响旅程和人工预览 | 通过确认后才随网站发布 |
| 网站实现、内容适配器或运行时配置 | 运行与影响范围对应的类型、测试和构建检查 | 有用户可见变化时必须进入精确提交预览 |

路径过滤只能在正式内容集和前端目录确定后实现，不能仅因文件位于 `docs/content/` 就假定它会进入公开网站。内容集选择、示例隔离和 background 禁止构建规则继续以 [架构](05_架构.md) 为准。

## 内容更新与发布流程

1. 在任务分支修改规范维护位置。事实变化先更新 background；公开文案仍须经过内容准备和人工审核进入正式内容集，构建不得直接读取 background。
2. 自动执行仓库文档校验、内容契约和引用校验。关键字段与可选字段分别阻断还是警告，等待 H07 决定；前端 lint、类型、测试和构建命令等待 H01～H05、H14 决定。
3. 对用户可见变化完成优化构建，并生成与精确提交 SHA 对应的不可变预览地址。会随新提交移动的分支别名不能单独作为人工确认依据；无独立可见增量的变更仍须按 H13 已确认原则完成适用的构建和测试。
4. 预览使用禁止搜索引擎收录的配置。`noindex` 只控制收录，不等于访问受限；确需限制访问时继续使用受限 Ubuntu/ECS 或平台访问控制。
5. 产品负责人按 I01 在合并请求中确认。检查单位是 I03 定义的页面适用内容包，并覆盖受影响的地域配置、网站版本和可达状态。常规内容更新只检查受影响页面与有代表性的窄屏、宽屏，不重复完整阶段矩阵；阶段验收才执行 I04 的四类视图与完整代表性任务。
6. 人工确认后若提交再次产生用户可见变化，原确认不再覆盖新提交，必须重新检查新的 SHA 和预览。
7. 所有必需检查与人工确认通过后，合并到届时确定的生产来源分支。生产部署从合并后的提交重新选择正式内容集并构建，不直接把示例预览或未合并分支当成正式版本。
8. 部署后检查首页、受影响页面、404、当前地域与网站版本隔离，以及本次变更涉及的主要恢复路径。部署记录至少能回溯提交 SHA 和生产部署结果，不另建审批数据库。

首个可部署浏览的稳定演示版本仍按 H12 试用 Cloudflare Pages；该试用不固定长期供应商、正式域名或生产分支。若延续当前分支习惯，建议由 `main` 承担生产来源、`dev` 承担集成，但实际映射与必需检查等待 H13 获得人工授权后统一确定。

## 阶段节奏

- M0 验证专业网站骨架、技术架构、视觉基线和插件接入面。
- M1 交付首批地域配置、基础购票与观演凭据，以及既定公开历史内容。
- M2 交付黄牛支线、完整七结局导演，并按既定顺序准备后续地域配置。
- M3 交付旧酒神历史网站及其独立内容、搜索、访问内异常进度和高成本视觉。

每阶段单独验收，但这不阻止阶段之间发布必要修正或经审核的内容更新，也不把功能目录中的候选自动升级为实现承诺。阶段任务重排、验收表和预览分类仍等待全部 P0 决策完成后由人工统一授权，不因 I06 自动生成。

## 正式域名与搜索引擎收录

预览阶段保持禁止收录。正式域名和索引只在人工确认以下条件后启用：

- 名称、标志、非官方说明、正式素材权利和发布说明已经确认；
- 生产构建只读取正式内容集，不包含 `docs/content/90_examples/`；
- 当前启用地域配置和网站版本的标题、描述、canonical、`hreflang`、站点地图与真实 404 已校验；
- 未启用、缺少必要资源或未实现当前网站版本的地域组合不生成公开页面或替代索引；
- M3 正式发布时已经用人工确认的泰拉日期替换 `0000`；
- 正式域名的手机和电脑核心任务通过对应阶段验收。

开放收录是独立人工动作，不从部署成功、域名存在或平台环境名自动推断。后续新增地域配置或网站版本时，只把已经完整通过验收的组合加入站点地图和 `hreflang`。

## 上线后功能排序

下一项功能只按当前阶段目标、人工体验反馈和实现成本共同判断，不按功能数量、视觉冲击或入口点击量自动排序。内容、素材和审核准备度可以作为可执行性说明，但不建立机械评分模型。

尚未批准的创意继续保存在 `../../planning/03_后续功能候选.md`。重新评估必须先证明它服务当前页面任务，并由产品负责人批准后才能建立模块、旅程和开发批次；I08 不要求启用访问统计，也不改变 H15 的待决定状态。

## 发布回退

Git 提交是代码与内容版本的最终来源。发生由当前发布引入的阻断问题时：

1. 找到最近一个已经成功部署并通过校验的生产提交，而不是任意较早提交或预览部署。
2. 可以先用托管平台回退到该生产部署以快速恢复，但平台操作不能成为唯一记录。
3. 随后在仓库中使用 `git revert` 或正常修复提交恢复可发布状态；不得强制推送、重写历史或人工复制旧构建覆盖。
4. 从修正后的 Git 提交重新构建正式内容集并部署，使生产环境和仓库重新一致。
5. 重复最小线上检查，并记录故障提交、恢复提交和生产结果。

代码与内容随同一个提交回退，避免页面实现和内容集错配。带版本号的浏览器本地状态遇到不支持的较新版本时应安全忽略或退化为会话内存，不能让回退后的页面崩溃；当前不为此预建复杂迁移系统。托管平台整体故障不属于旧提交可修复的发布回归，应单独处理。
