# 设计系统

## 核心气质

M0 表网站采用新酒神时期中明亮、现代、可信、最接近常规剧团营业状态的一面：现代巡演节目册、可信剧院官网、观演凭据、报章、黄铜编号、帷幕与聚光。保留猩红剧团的舞台主体，但纸张、黄铜和帷幕只作适量强调，不以古董档案、诡异、惊悚或污染特效作为 M0 气质。M3 里网站才承载“舞台侵入现实、档案被改写、角色替代人”等 creepypasta 类表达；它不是随机 glitch，也不是表网站换肤。

起始基础色（同人设计建议，不是官方品牌规范）：

```css
:root {
  --stage-black: #0b090b;
  --curtain-red: #6f0d1b;
  --diamond-red: #b51632;
  --paper: #e7ddc8;
  --brass: #9b7843;
  --cold-blue: #4c78a8;
  --bruise-violet: #493657;
}
```

这些值只形成共享的颜色起点，不直接充当所有组件的最终颜色。组件读取纸面、正文、强调、边框、危险和异常等语义 token；每个 `siteEditionId` 分别把语义映射到基础色：

- `new-dionysus`：M0 实现；浅纸面、清晰深色正文、克制深红与黄铜强调，保持明亮、现代和正常营业感。
- `old-dionysus`：M3 设计时再建立；可以使用更暗纸面、更危险的猩红、冷蓝或瘀紫异常色，不在 M0 预建空映射。

两套映射随网站版本固定，不是用户可切换主题。地域配置只能覆盖字体、格式和少量文化性装饰，不能覆盖网站版本的整体明暗与叙事身份。M3 不得反向改变表网站 token 的语义。

## 版式与形状

- 页面使用中等留白、易读正文和明确重点卡片；视觉密度只调整阅读节奏，不删减既定信息。
- 手机与电脑承载相同任务；手机先形成连续纵向阅读流，电脑再利用宽度扩展舞台式构图。
- 常规卡片、按钮和输入控件使用直角或小圆角与细边框。
- 票券切口只用于观演凭据、票务结果等确有票务语义的少量重点组件，不作为全站卡片装饰。

## 可扩展视觉层

- 新酒神表网站：M0 默认；明亮、现代、可信，留足纸面阅读空间。
- 旧酒神历史网站：M3 独立实现；可以使用涂黑字符、划改、撤回公告、被叉除的人物图、灾难新闻、错装页与异常动效，拥有独立 token、组件和页面结构。
- 古堡残响、罗德岛调查等其他叙事层：仍是未决定候选，不因 M3 旧网站确定而自动成为网站版本。
- 新酒神异常层：只作为 `../../planning/03_后续功能候选.md` 中的待审创意，不进入现行模块或阶段规划。

地域配置可以覆盖字体、排版细节、日期格式、少量节目册结构和局部装饰，但不能改变同一网站版本的核心任务顺序。表网站和里网站可以使用不同组件体系与页面数量；它们只复用语义确实一致的底层工具。字体方案必须覆盖汉字、假名、拉丁字母、西里尔字母、希腊字母和波兰语附加字符；缺少对应字库时使用可读的系统字体回退。

## 历史网站异常层级

M3 里网站使用四段可区分的视觉层级，而不在每次访问时随机生成强度。有效探索数、阈值和重置语义以 `docs/content/05_site_editions/README.md` 为唯一内容契约。

- 基线：保持可信的旧网站排版，只显示内容集预置的少量冲突。
- 低强度：使用局部划改、纸面偏移或不稳定批注，但不改变任务顺序。
- 增强：逐步增加涂抹、错装页、被划除人物和新闻冲突，始终保留可读原始内容。
- 饱和：维持经设计的最高异常水平，继续探索不再增加强度或叠加新特效。

稳定演出版隐藏后三段的渐进呈现，但不删除基线中已审核的冲突记录，也不重置本次访问进度。任何层级都不得遮挡捕获栏、返回当前网站、稳定演出版和错误恢复操作。

## 动效词汇

允许：开合帷幕、聚光移动、纸页翻动、改稿划线、偶人丝线、低密度舞台粉尘。每个效果必须有静态降级；异常不覆盖原始证据文本。

避免：高频闪烁、全站噪声抖动、强制晕动、无法停止的滚动、突然自动播放、用故障效果代替信息层级。

## 响应式

- 桌面：节目栏 + 可选侧边增强；证据或编辑预览可双栏对照；安装购票模块后显示完整分区图。
- 手机：单列纵向内容；安装购票模块后仍显示完整分区图，不改成仅有分区卡片的替代界面。
- 席位只选择 S/A/B/C/D/包厢等分区，不选择具体座位；颜色必须同时配合文字、边界或纹理，并提供等价列表。
- 低带宽模式保留正文、剧目、观演提示、结局与观演凭据文字版。

## 无障碍是世界观内的“稳定演出版”

- 拖拽有按钮替代，计时有无计时模式，Canvas 有文本视图。
- 稳定演出版始终可达。“闭幕”只在叙事叠层打开时立即停止该层动画和污染并关闭叠层；历史网站使用捕获栏和浏览器后退返回当前网站。这些操作不能做假按钮或反转。
- 证据级别同时用文字/图形，不只用色彩。
- 惊悚、自伤、感染与精神影响内容可以做提示和分级，但不强制替人员做内容取舍。

## 图像与权利轨道

信息库不保存或索引游戏原图。M0 不依赖外部图片、官方原图或 AI 示例位图；公开站使用以下项目原创且可替换的视觉源：

- 名称固定为 Crimson Troupe 的文字字标与简单几何临时 SVG 标志；M3 可另设历史版本。
- 首页原创 SVG 舞台或帷幕构图，并使用经初审的示例演出标题排版；能力受限时显示静态构图。
- 人物使用姓名首字、舞台职位、部门和原创纹章式占位卡，不绘制具体角色外貌。
- M0 剧目封面和场馆图使用可替换 SVG 模板，按记录改变颜色、编号、标题排版和几何图形；M3 不受该模板约束。
- 票面、印章、图标和纹理以项目原创 SVG 为源，纹理由 CSS/SVG 生成，所有颜色由设计 token 控制。
- favicon、应用图标和分享图使用临时原创源；分享图按 `localeProfileId + siteEditionId` 使用当前公开内容排版，可以在构建时导出派生位图。

模块不得各自引入图标库、纹理包、外部图片或硬编码颜色。未来经人工批准的正式素材按现有尺寸、语义和数据接口整体替换；官方图、字体、商标、域名和“是否可能被误认作官方站”仍由人工在发布前做权利与风险评估。本项目不保存、构建或播放音频素材。风险提示不替代创作决策。

## 观演凭据组合印章

观演凭据使用一个由七个预定义 SVG 图层组成的原创印章。每个稳定成就 ID 只对应一个 `stampSegmentId`；重复结局不增加笔画、孔位或图层，集齐七项后形成完整徽记。造型不得依赖中文“正”字等单一语言的阅读规则，也不得复制游戏内现成票戳。

印章图形负责提供累积体验；路线结果名称与成就说明只出现在结算卡和成就视图，不列在凭据上。成功结果按生成当时的唯一成就集合输出 SVG/PNG，失败结果不生成凭据；已经下载的文件不因之后解锁新成就而改变。完整状态和渲染规则以 `../04_modules/01_购票体验契约.md` 为准，七段造型仍待视觉审核。

## 组件预览

示例内容初审后、完整页面开发前，agent 使用同一批内容制作两套小型风格板和关键页面线框。两套方案都必须遵循已经确定的 M0 表网站气质、信息密度、配色边界、形状和原创素材策略，不能以 M3 恐怖风格充当其中一个候选。人工选定一个视觉基线后，再建立正式 token 和组件。

开发环境提供轻量组件展厅，直接展示正式按钮、卡片、提示、地域切换、票面和状态组件。展厅只复用选定方案的生产组件、token 与经人工初审后进入独立数据集的示例内容，不引入 Storybook 等独立工具，也不为预览维护第二套样式。
