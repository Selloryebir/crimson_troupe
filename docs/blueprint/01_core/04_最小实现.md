# 最小实现（M0）

只实现这一层，也必须像一个可用的专业演出机构官网，而不是概念首页。

## 路由与页面

M0 以七类公开页面与任务验证完整信息架构，但只形成五个主导航栏目：今夜、演出日历、剧目、剧团、巡演与到访。演出详情属于下钻页面，搜索与稳定演出版属于工具；页面类别不等于实际路由数量。

- `/`：跳转到规范入口 `/yan/`。
- `/yan/`：主视觉与近期演出、公告、推荐剧目、剧团简介、到访提示。
- `/yan/schedule`：默认未来场次列表，可切换月历，并按剧目、城市、场次状态和可访问形式筛选。
- `/yan/schedule/:id`：世界内日期、场馆、演职员、节目、时长、幕间、状态、其他日期；主操作查看状态或预约说明。
- `/yan/troupe`：剧团、当前公开组织、部门与成员、时间边界；M0 不建立人物详情路由。
- `/yan/troupe/join`：静态“加入我们”信息；只从剧团页次级入口或页脚进入，不提供试镜、报名或用户输入。
- `/yan/repertoire`：剧目列表。
- `/yan/repertoire/:slug`：单个剧目详情、相关场次与公开说明。
- `/yan/visit`：在一个页面内展示三个示例地点、抵达窗口、首次观演和必要提示；M0 不建立场馆详情路由。
- `/yan/search`：只搜索炎国配置的剧目、场次、成员、地点、获准公开的专名和同语言别名，并提供正常无结果恢复。

其他地域配置复用相同页面路径结构，不建立第二套路由表。例如维多利亚演出日历为 `/victoria/schedule`。

## 输入边界

核心壳与模块的实际输入路径分别以 [架构中的核心壳信息输入](05_架构.md#核心壳信息输入) 和对应模块 YAML 为唯一维护位置，本页不复制路径清单。background 只在内容准备阶段提供人物、剧目、地点、组织、专名和时代边界等事实锚点；构建阶段只读取通过初审后进入 `docs/content` 的选定内容集。

## M0 编码前的内容准备

当前决策阶段不生成示例内容。进入 M0 编码前按以下顺序完成独立内容准备：

1. agent 结合页面任务、内容表达、沉浸效果和既有 background 事实边界生成示例草案。
2. 人工初步审核示例是否适合 demo；该审核不等同于正式内容发布批准。
3. 只把通过初审的内容存入 `docs/content/90_examples/01_m0/`，并按网站版本与地域配置契约形成可选内容集；不把 background 路径写成构建输入。
4. demo 构建读取示例集；正式发布不得引用该目录，也不得与人工编辑并启用的内容自动合并。

示例集使用 3 个剧目、6 个场次、6～8 名成员和 3 个地点。每个剧目至少关联一个场次，至少一个剧目有两个不同日期；三个地点都被使用，场次状态与可访问形式形成有效差异，并至少提供一种正常零结果组合。

## M0 完整开发前的视觉选择门

示例内容初审后，agent 使用同一批内容制作两套小型风格板和关键页面线框，至少覆盖首页桌面与手机片段、演出详情、日历或筛选、剧团成员卡和常规状态组件。两套方案都使用现代巡演节目册与可信剧院官网方向、中等留白、表网站语义配色、克制形状和项目原创 CSS/SVG，不以 M3 恐怖风格作为候选差异。

人工选定一个视觉基线后，才建立正式设计 token、组件展厅和完整 M0 页面。风格板不是第二套运行时主题，也不进入正式导航或生产构建。

## 验证阶段默认

- M0 使用新酒神时期的公开营业层，不实现旧团、古堡与多时间层切换。
- 新酒神表网站采用明亮、现代、可信的剧团设计，保留节目册、帷幕和舞台主体，但不实现 M3 的涂黑、异常新闻与 creepypasta 类表现。
- M0 只生成炎国配置并验证 i18n 插件接入面；架构确认可部署后，首个多语言版本的炎国、东国、维多利亚和哥伦比亚覆盖全部 M0 页面并通过同一验收后共同发布。
- 莱塔尼亚是后续六个配置中的第一优先，但仍在 M2 黄牛支线与七结局导演完成后开始；其他五个配置顺序待人工安排，研究候选不生成路由、选择器或货币映射。
- 静态“加入我们”属于 M0 剧团页面家族。单场次购票和观演凭据在 M1 实现，黄牛小游戏在 M2 实现，旧酒神历史网站在 M3 实现；彩蛋与其他候选功能等待单独批准。不预建票篮、改签或本地凭据档案。
- M0 使用现代巡演节目册与可信剧院官网方向；页面采用中等留白、易读正文、明确重点卡片、直角或小圆角和细边框。
- 主视觉、临时标志、人物占位、剧目封面和场馆图使用项目原创 CSS/SVG 与纯色占位，不依赖外部图片、官方原图或 AI 示例位图，也不实现 WebGL 或其他 3D 特效。
- M0 常规组件不使用票券切口；该造型在后续批次只用于观演凭据、票务结果等确有票务语义的少量组件。分享图按当前地域配置和网站版本使用公开内容生成。
- 普通页面缺译可以回退炎国并标注“中文原文”；搜索索引与结果不得使用该回退，也不得匹配其他地域配置或语言字段。
- M0 只生成 `yan + new-dionysus` 搜索索引，不生成历史网站路由、内容或空索引。

E12 只固定彩蛋的全局表现边界，不批准任何具体实现。彩蛋不得形成需要关闭的持续界面；404、Miss.Christine、鸭爵或其他候选只有在单独 journey 获批后才能进入开发。

首屏先可用，再启幕；项目不实现声音播放；稳定演出版始终可达。“闭幕”只在后期叙事叠层打开时关闭该叠层，不在 M0 预建无功能入口。不实现剧透状态，也不为 M0 预建完整叙事或历史网站状态机。

M0 首屏保持简洁，正文按基础任务、补充设定和批注逐层展开；陌生访客所需解释融入标题小字、术语短注或可展开说明。详情页末尾只展示少量规则可解释的相关场次、剧目或成员。主内容使用世界内日期，服务器发布日期只在用户主动查看的资料证据区单列。

## 构建与受限部署门

完整实现提交前，使用锁定的运行环境和依赖完成优化构建，并在本机启动构建产物检查全部 M0 路由。M0 合并或阶段验收前，把同一提交部署到另一台 Ubuntu 或受访问控制的 ECS，通过手机和电脑从另一设备访问首页、五个主导航任务、演出详情、搜索、正常无结果和 404。

无域名不等于受限访问；使用公网 ECS 时仍需由人工配置安全组、白名单、VPN 或内网。该验证不决定未来正式托管平台，也不要求每个小提交都部署远端。

## 测试与人工验收范围

- 单元测试覆盖内容适配器、地域配置与网站版本搜索隔离，以及剧目、场次、成员、地点等关键数据关系。
- 浏览器测试覆盖 M0 核心旅程的主流程和恢复路径；后续插件安装时再增加对应测试。截图只用于辅助观察，不能替代行为断言。
- 自动化浏览器以 Chromium、Firefox 和 WebKit 三类引擎为代表；支持主流现代 Chrome、Edge、Firefox、Safari，以及当前和上一主版本的 iOS Safari、Android Chrome，不支持 IE。
- 人工验收使用窄屏手机、普通手机、笔记本和宽屏四类代表性视图，组合覆盖五个主导航任务、演出详情、搜索、正常无结果和 404，不做页面与宽度的全组合测试。
- M0 只验炎国配置；首个多语言版本另以代表性脚本检查四个配置的全部 M0 页面、文本与布局，并在同一验收通过后共同发布。

## 首次持续预览试用

首个可部署浏览的稳定演示版本（当前讨论简称 `demo_stable`）暂用 Cloudflare Pages 连接 GitHub，为精确提交生成独立预览。试用验收至少确认优化构建、静态路由、404、禁止预览收录，以及手机和电脑可访问性；完成真实合并请求预览后，由产品负责人决定是否沿用或更换平台。

Cloudflare Pages 预览不替代本页的 Ubuntu 或受限 ECS 验证，也不决定正式托管、域名和搜索引擎收录。前端技术基线已固定为 Astro + TypeScript 静态生成；首次试用直接部署静态构建目录，不引入 Cloudflare 运行时适配器、Pages Functions 或 SSR。当前仍处于内容准备门之前；H13 已固定门禁规则，但前端工程、平台配置和部署工作流只能在前端工程与首个成功检查存在后建立，本次不提前创建。
