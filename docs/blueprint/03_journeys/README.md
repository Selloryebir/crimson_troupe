# 用户旅程库

这里不是三个“示例流程”，而是网站开发的任务地图。

- `journey_registry.yaml`：24 条可审阅旅程；每条含入口、路由、模块、主流程、恢复和产出。
- `maps/`：按任务域合并的 Mermaid 流程图，避免为每条短路径制造一个文件。
- `../07_功能目录.csv`：每项功能都有主旅程、辅助旅程和建议开发批次。
- 旅程只引用模块标识，不复制资料输入；核心壳输入见 `../01_core/05_架构.md`，可插拔模块输入见对应模块 YAML。

## 开发批次

- M0：五个主导航任务、演出与剧目详情、地域隔离搜索、单页到访、静态“加入我们”、故障恢复、炎国配置与 i18n 插件接入面。
- M1：先交付首批四个地域配置，再安装单场次世界观购票、基础结局导演、30 天成就状态和 SVG/PNG 观演凭据，随后补充演出回顾、新闻和剧务历史。
- M2：首先完成黄牛平台小游戏与七结局导演，再按人工决定启用后续地域配置。
- M3：旧酒神历史网站及其独立内容、搜索、访问内异常进度和高成本视觉。

项目不建设通用档案馆、持续活动系统或声音播放能力。未批准的幻觉、片场、剧匣和幕间游戏只保存在 `../../planning/03_后续功能候选.md`，不构成模块或旅程。

## Agent 使用顺序

1. 从功能目录找到功能的“主旅程”。
2. 在注册表读取用户目标、前置模块和路由。
3. 打开对应领域流程图确认点击与恢复路径。
4. 读取核心架构或模块 YAML 中的输入、降级和验收条件。
5. 先通过 M0 等价任务，再挂接沉浸层。

旅程描述的是待审设计意图，不是已经实现的页面，也不代表所有条目必须上线。
