# 内容与创作应用

本目录保存基于事实产生、但不能当作《明日方舟》既定事实的编辑判断、创作口径、工作译和内容本地化。每项应用应链接到 `../background/` 的事实依据。

| 目录 | 内容 |
| --- | --- |
| `01_world/` | 国家文化模型、世界观页面口径、地点与票务用法 |
| `02_crimson_troupe/` | 猩红剧团叙事快照、关系应用和安全边界 |
| `03_localization/` | 泰拉语言研究、工作译、跨语言矩阵和审核队列 |
| `04_performance/` | 客席岗位推演、方法与角色选择边界 |
| `05_site_editions/` | 表网站、历史网站快照、内容集和搜索隔离契约；不保存实际示例记录 |
| `90_examples/` | 经人工初审后供 demo 使用的 agent 生成示例内容；在 M0 内容准备阶段建立 |

本目录不保存运行时地域配置、现实语言标签、回退规则或组件实现；技术 i18n 见 `../blueprint/05_i18n/`。官方中英日专名见 `../background/03_terminology/`。

## Background 与网站构建边界

`../background/` 是独立事实时间线和信息源，只供人工创作、agent 生成草案和事实边界核对。前端构建、模块和公开搜索不得直接读取、转换或索引 background；准备出的内容必须先进入本目录，经人工确认后才能成为某个内容集的输入。

事实记录、表网站公开叙述和里网站历史叙述互不覆盖。内容可以通过来源路径与自然定位字段回溯 background，但这种关联只用于准备和审阅，不构成运行时依赖。

## 示例内容生命周期

当前决策阶段不创建或填充 `90_examples/`。进入 M0 编码前，agent 先依据网站任务、内容表达、沉浸效果和 `../background/` 的事实边界生成一套草案；人工初步审核其 demo 适用性后，才把通过的内容写入 `90_examples/01_m0/` 并交给最小实现读取。

- 示例数据使用 3 个剧目、6 个场次、6～8 名成员和 3 个地点，并有意覆盖关联、筛选差异和正常零结果。
- 事实实体通过自然定位字段关联 `../background/`；虚构日期、场次状态、抵达窗口、公告和运营安排只存在于示例内容中。
- 示例内容与人工编辑并启用的内容复用字段结构，但不得在一次构建中自动合并。
- 同一批经初审示例内容用于制作两套 M0 小型风格板和关键页面线框；人工选定视觉基线后才进入完整页面开发，不为两套候选复制内容集。
- 正式发布不得引用 `90_examples/`。需要采用的示例必须复制或重写到正式内容位置并再次人工确认，不能在示例目录中原地改为正式内容。
- `90_examples/` 是内容状态边界，不在每条记录中重复维护同义的示例状态字段；构建入口负责选择一个内容集并阻止正式发布引用示例目录。

正式替换按页面适用的文字、图像、已启用地域资源和可达状态整包验收；共享品牌资产、组件和设计 token 不复制进内容目录。完整边界见 [内容边界](../blueprint/01_core/02_内容边界.md#正式内容替换与验收)。

内容通过人工确认后怎样进入预览、正式发布和回退，统一见 [发布与维护](../blueprint/01_core/07_发布与维护.md)；不是每一项 `docs/content/` 研究或说明变更都会自动成为公开网站输入。
